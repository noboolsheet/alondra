# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Marketing/landing site for **Alondra**, a music school in Miami-Dade & Broward (in-home lessons, teachers, enrollment). Single-page-app style multi-page site built with Vite + React + TypeScript + shadcn-ui + Tailwind. Generated and round-tripped through [Lovable](https://lovable.dev) — pushed commits sync back to the Lovable project, and `.lovable/plan.md` holds the original build brief.

The site's copy is governed by a marketing strategy with explicit limits on what the academy may claim (see **Claims discipline** below). Treat those limits as product requirements, not style preferences.

## Commands

```sh
npm run dev          # Vite dev server on http://localhost:8080 (host "::")
npm run build        # production build to dist/
npm run build:dev    # build in development mode
npm run lint         # eslint over the repo
npm run test         # vitest run (single pass)
npm run test:watch   # vitest watch mode
npx vitest run src/test/routes.test.ts   # run a single test file
npm run images       # optimize imagen-sources/ → public/images/ (.webp), incremental
npm run images:watch # same, but watches imagen-sources/ and converts on the fly
```

`bun.lockb` and `package-lock.json` are both committed; npm is the assumed package manager.

**Image pipeline.** Drop original full-size images into `imagen-sources/`; `scripts/optimize-images.mjs` (sharp) writes web-optimized `.webp` copies into `public/images/`, preserving subfolders. Reference them in components as `/images/<name>.webp`. The optimizer is incremental (skips up-to-date outputs) and runs automatically before `npm run build` via the `prebuild` script.

## Architecture

**Routing is generated from one map, and the URL carries the language.** `src/i18n/routes.ts` is the single source of truth: every page has a `PageKey` and one slug per language. English lives at the root, Spanish under `/es`, French under `/fr`, and the slugs themselves are localized so each version can rank for what people type in that language (`/pricing`, `/es/precios`, `/fr/tarifs`).

`src/App.tsx` wraps everything in `MotionConfig` → `QueryClientProvider` → `ThemeProvider` → `TooltipProvider` → `BrowserRouter` → `LanguageProvider`, mounts both toasters (`Toaster` from shadcn + `Sonner`), `ScrollToTop` and `RouteEffects`. The `<Route>` elements are generated by iterating the route map — they are not written by hand.

- **To add a page:** add a `PageKey` with its three slugs in `routes.ts`, then map the key to a component in the `PAGES` record in `App.tsx`. Nothing else needs touching.
- **To rename a slug:** add the old path to `LEGACY_REDIRECTS` in `routes.ts` *and* to the matching table in `server/index.mjs`, or the old URL's ranking and inbound links are lost.
- **Never hardcode a path.** Use `<PageLink to="pricing">` (`src/components/PageLink.tsx`), which resolves the URL in the visitor's current language. A literal `<Link to="/pricing">` silently throws a Spanish visitor into the English site.

**Pages compose sections.** `src/pages/*` are thin — each wraps `<Layout>` (Header + animated `<main>` + Footer) around section components from `src/components/`. `Index.tsx` stitches the homepage (Hero, Stats, GoogleReviews, Pedagogy, InstrumentsGrid, Formats, TeachersGrid, CoverageMap, FAQ, CTABanner). To change page content, edit the section component, not the page.

**Internationalization is the core cross-cutting concern.** The site is trilingual (en/es/fr). All copy lives in `src/i18n/translations.ts` as a strongly-typed `Dict` (English is the source-of-truth type; `es`/`fr` must match its shape). Components read copy via `const { t } = useLang()` (from `src/i18n/LanguageContext.tsx`) and index into `t.*`. **When adding user-facing text, add a key to the `Dict` type and fill all three languages — do not hardcode strings in components.**

The language comes from the **URL prefix**, not from state: `langFromPath()` reads it, `useLang()` exposes `lang` and the current `page`, and `setLang()` navigates to the same page's URL in the new language. `localStorage` (`alondra-lang`) only remembers the preference; it never overrides the URL, and `/` always serves English so the canonical URL and its content can't disagree. A broken link under `/es/` still resolves as Spanish, so its 404 renders in Spanish.

**SEO metadata is written per route.** This is a client-rendered SPA with one static `index.html`, so `usePageMeta()` (`src/lib/pageMeta.ts`) sets the title, description, canonical, `hreflang` set (plus `x-default`), Open Graph and Twitter tags on every route change, from `t.meta[pageKey]`. On a 404 it writes a not-found title, adds `noindex` and **removes** canonical/hreflang, so an unknown URL can't claim to be a real page.

`vite.config.ts` emits two files at build time from the same route map, so neither can drift: `sitemap.xml` (with hreflang alternates) and `routes.json`. `server/index.mjs` reads `routes.json` to answer a real **404** on unknown paths instead of serving the SPA with a 200, which Google reads as a soft 404. If `routes.json` is missing the server falls back to answering 200 everywhere — a stale route list must never take the site down.

**Analytics.** GA4 is loaded from `index.html`, with a `ga-disable-*` guard so `npm run dev` on localhost doesn't pollute production data. Because this is an SPA, the tag alone only ever reports the landing page — `usePageviews()` (`src/lib/analytics.ts`) emits a `page_view` on each subsequent route change. `track()` in the same module is a safe no-op when gtag is absent (ad blocker, local dev).

**Forms post to a real mail backend.** `server/index.mjs` is an Express server (nodemailer over Gmail SMTP) exposing `POST /api/send-contact` and `POST /api/send-application` (honeypot + validation + CV attachment). `ContactForm` and `ApplicationForm` `fetch()` these endpoints with real `sending`/`submitError`/success states. `RegistrationWidget` embeds the third-party **My Music Staff** scheduler in an iframe (loaded from `public/mms-widget.html`), hardened with a loading skeleton + timeout fallback (`useIframeStatus`, also used by `CoverageMap`). The hero's primary CTA is a **free discovery call** (routes to contact) — the academy deliberately does **not** offer trial or free classes.

**UI layer.** `src/components/ui/*` is the standard shadcn-ui set (Radix primitives) — generally don't edit these; compose them. `src/components/*` (non-`ui`) are the app's own sections. Icons via `lucide-react`, animation via `framer-motion`, data-fetching scaffolding via `@tanstack/react-query` (present but the site is static).

## Claims discipline

The site previously published claims the academy cannot support, and they were removed deliberately. Do not reintroduce them, and apply the same test to new copy: **would a document back this up?**

- **Never** promise guaranteed results, cognitive/clinical benefits, "the standard of the world's finest conservatories", or superlatives like "best academy in Miami".
- The "500+ students" figure belongs to **Ilena's career**, never to the academy — it has a handful of active students.
- **Music therapy** may appear in Ilena's and Olivia's biographies as past experience, phrased in the past. It must never be offered as a service or used as a present-tense title: US board certification (MT-BC) requires a credential they do not hold.
- Don't announce recitals until they are actually scheduled.
- Describe what Alondra's method does (**technique, rhythm, music reading, interpretation**) — never claim other academies don't teach it.
- `src/data/googleReviews.ts` holds real reviews, stored per language with an `originalLang`. Only feature reviews from actual families: anyone with another relationship to the academy (teachers, collaborators) must not appear, and translations are labelled as such.

## Conventions

- **Path alias `@/` → `src/`** (configured in `vite.config.ts`, `vitest.config.ts`, `tsconfig`). Use it for all internal imports.
- **Styling via Tailwind + CSS variables.** Brand tokens and custom component classes live in `src/index.css` (`@layer components`): use `container`/`container-wide`/`container-full` for page width, `btn-cta`/`btn-outline` for buttons, `eyebrow` for section kickers. Brand colors are HSL CSS vars (`--brand-purple`, `--brand-yellow`, `--brand-lavender`) surfaced through `tailwind.config.ts` (`primary`, `accent`, `lavender`, etc.). Fonts: `font-serif` (**Fraunces**) and `font-sans` (**Nunito**), loaded via `@fontsource` in `main.tsx`. The dark theme is the default and is part of the brand — don't switch the site to light by default.
- **Tests** use Vitest + Testing Library in a jsdom env; globals are enabled and `src/test/setup.ts` runs first (jest-dom matchers, plus `matchMedia` and `IntersectionObserver` polyfills). Test files match `src/**/*.{test,spec}.{ts,tsx}`. The `IntersectionObserver` stub reports elements as visible **asynchronously**, like the real one, so assert a `whileInView` reveal with `waitFor`/`findBy*`, not a synchronous `getBy*` + `toBeVisible()`.
- `docs-sources/` holds reference material for the marketing strategy (dossier, briefs, spreadsheets). It is **git-ignored on purpose** — nothing there is served by the site. Don't `git add -f` it back in.
- ESLint has `@typescript-eslint/no-unused-vars` turned **off** and `react-refresh/only-export-components` as a warning. Two pre-existing errors in `src/components/ui/` (shadcn boilerplate) are expected.
